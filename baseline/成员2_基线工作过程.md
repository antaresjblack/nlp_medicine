## 1. 数据检查与评测协议（前置步骤）

**做了什么**：`data_check.py` 只读检查 train/dev/test 的结构、实体索引、文本切片一致性、标签合法性，并统计重叠/嵌套实体。输出 `outputs/data_check_report.txt`。

**关键发现**：dev 的 270,417 个字符位置中有 3,982 个（1.47%）带嵌套多标签（如"腹部"同时标注为 bod 和 sym）。这个事实决定了全部评测设计：

- 实体级严格 micro-F1（start+end+type 全对）为主指标，直接使用原始嵌套标注——这是 CBLUE 官方口径；
- 单层 BIO / 单层字符标签无法无损表示嵌套实体，因此任何字符级指标只能是**补充指标**。

**为什么先做这步**：所有方法需要同一把尺子；口径不定，后面的对比都不可信。

## 2. 统一评测框架与 token 级指标的设计

### 2.1 框架构成

| 文件 | 作用 |
|---|---|
| `span_utils.py` | 统一 span 格式（`text[start:end+1] == entity`）、实体键、多数标签消歧 |
| `metrics.py` | 实体级严格 micro P/R/F1 + 逐类别统计 + 两组字符级补充指标 + 逐条错误记录 |
| `evaluate_saved.py` | 对已有预测文件重新评测；`--batch-dir` 批量刷新历史指标文件 |

### 2.2 最长投影 token 指标的问题与改进

**最初设计**：token 级补充指标采用"最长非重叠实体投影"——每字符位置只保留最长实体的一个标签。运行后发现它存在**系统性偏差**：

> 投影会丢弃嵌套实体的内层标签。若模型恰好正确预测了金标的内层（如词典命中 bod 的"腹部"，而金标是 bod⊂sym 嵌套），投影后的金标只剩外层 sym，这个**正确的预测被误记为误报（fp）**，导致 Precision 被系统性低估 2~3 个百分点（词典最佳：投影 P 0.5350 → 多标签 P 0.5606，tp +2,204 与 fp −2,204 完全对消）。

**改进**（不替换、只补充）：新增**多标签字符级指标**（`char_multi_label_*`）——每字符位置保留全部实体标签集合（金标直接用原始嵌套标注），逐标签微平均 P/R/F1 + 逐位置标签集合完全一致的精确准确率；同时为两种口径都补充逐类别明细（`token_per_label` / `char_multi_label_per_label`）。两组口径在报告中分别使用固定措辞：

- 投影口径：基于最长非重叠实体投影的字符级补充指标；
- 多标签口径：基于保留全部实体（含嵌套）的逐标签多标签字符级补充指标。

**结果**：两种口径的方向差取决于模型是否输出嵌套预测。多标签口径有两个相反效应：金标侧恢复内层（翻正"命中内层却被误记 fp"的错案）使其占优，预测侧不丢弃误报内层（多计 fp）使其吃亏。单层输出的方法（longest 词典、纯规则、小模型）预测几乎无嵌套，效应二为零，因此多标签 F1 ≥ 投影 F1（如小模型 0.5241 vs 0.5373，差 +0.0132）；而 exact 词典保留所有重叠匹配、预测了大量无根据的嵌套内层，效应二压过效应一，多标签 F1 反而更低（0.4977 vs 0.4815，差 −0.0162）——多标签口径因此还能暴露"模型是否在乱输出嵌套层"。指标代码演进后，用 `evaluate_saved.py --batch-dir outputs` 一次刷新全部历史 metrics 文件（保留各方法的元数据字段），**无需重跑任何模型**。

## 3. 词典基线（7 组参数实验）

**原理**：从训练集实体建立"短语 → 多数标签"词典（`build_dictionary`，平票按字典序取确定性结果），在 dev 文本上匹配。`exact` 保留所有匹配（含重叠）；`longest` 贪心保留最长非重叠匹配。

**代码与输出**：`dictionary_baseline.py`；每组输出 `outputs/dictionary_{method}_min_count_{N}_min_length_{M}_predictions/metrics/errors.json`。

**参数组与结果对比（dev）**：

| 配置 | Entity P | Entity R | Entity F1 | Token F1 | 多标签字符 F1 |
|---|---:|---:|---:|---:|---:|
| exact | 0.1520 | 0.5415 | 0.2374 | 0.4977 | 0.4815 |
| longest | 0.2875 | 0.4916 | 0.3628 | 0.4977 | 0.5116 |
| longest + 长度≥2 ★ | **0.3496** | **0.4796** | **0.4044** | **0.5060** | **0.5188** |
| longest + 长度≥3 | 0.4610 | 0.3126 | 0.3725 | 0.4581 | 0.4647 |
| longest + 出现次数≥2 | 0.3067 | 0.4433 | 0.3625 | 0.4703 | 0.4873 |
| longest + 出现次数≥3 | 0.3162 | 0.4135 | 0.3584 | 0.4489 | 0.4664 |
| longest + 出现次数≥5 | 0.3217 | 0.3678 | 0.3432 | 0.4033 | 0.4218 |

**结论**：过滤单字实体最有效（长度≥2 最佳）；频次过滤整体不如长度过滤。

**错误分析**（`error_analysis.py`，最佳词典）：误报 22,465 / 漏检 14,914 / 边界错误 4,137 / 类型错误 1,249——误报是主矛盾。

**过程记录（不足与补全）**：出现次数≥3 和 ≥5 两组实验是最初 README 结果表中**缺失、后来补跑补录**的；补录后的结论不变（频次过滤仍不如长度过滤）。

## 4. 纯规则基线

**原理**：只使用 `pure_rule_baseline.py` 中人工编写的 9 条后缀正则（微生物/药物剂型/医疗程序/检验项目/疾病/症状/身体部位/设备/科室），**不读取训练集**；候选按"优先级 → 长度 → 位置"去重叠。

**结果**：Entity P 0.0908 / R 0.0312 / F1 **0.0465**；错误分布以漏检为主（17,203），因为规则只覆盖有限词尾模式。

**定位**：完全不依赖训练数据的启发式下界，用于方法谱系对比。

## 5. 字符级小模型（原理与基本情况）

**原理**：把 NER 当作逐字符分类问题。每个字符提取局部特征，用 LinearSVC 独立预测 BIO 标签（B-类型/I-类型/O），再用 `decode_bio` 解码为实体跨度并修复非法 I 转移。由于 CMeEE 存在嵌套实体，训练目标采用**最长非重叠实体投影**（单层 BIO 只能表达一层，这是已声明的限制）。

**基本情况**：
- 特征（初始 9 项）：当前字、前后各两字、是否数字/字母/ASCII、是否词典字符；
- 训练规模：81.1 万训练字符，14,176 个特征维度；
- 初始配置：C=1.0、class_weight=balanced、seed=42，训练约 366 秒。

**初始成绩**：Entity P 0.1161 / R 0.3513 / F1 **0.1745**——预测 61,408 个实体（金标仅 20,300），**病根是过度预测**：逐字独立分类没有序列转移约束，加上 balanced 权重抬高了少数类，模型"看见什么都猜是实体"。

---

## 6. 优化一：第一轮网格搜索（超参数调参）

**做了什么**：新建 `small_model_grid_search.py`，共享一次特征构建，遍历 `C ∈ {0.01, 0.1, 1.0, 10.0}` × `class_weight ∈ {balanced, none}`。结果存 `outputs/grid/`（不进入主汇总表）。

**结果**：

| C | class_weight | Entity F1 | 备注 |
|---:|---:|---:|---|
| 0.01 | balanced | 0.1742 | |
| 0.01 | none | 0.1957 | |
| 0.1 | balanced | 0.1809 | |
| 0.1 | none | 0.2274 | |
| 1.0 | none | **0.2281** | 当选（此时） |
| 1.0 | balanced | 0.1745 | 初始配置 |
| 10.0 | balanced | 0.1739 | 训练 103 分钟 + 收敛警告 |
| 10.0 | none | 跳过 | 见下 |

**发现**：class_weight=none 在每个 C 上都优于 balanced——balanced 把少数类权重抬得过高，正是虚报的根源；去掉后虚报减半（61,408 → 31,651），F1 从 0.1745 升到 **0.2281**。

**过程记录（不足）**：`C=10.0/none` **未运行**——其训练耗时约 100 分钟，且同 C 下 balanced 已确认更差（0.1739）、趋势明确无竞争力，故跳过并在 grid 汇总表中标记。此阶段的"最佳配置 C=1.0/none（0.2281）"**后来被第八节的第二轮调参覆盖**，旧数字存档于 `outputs/grid/`。

## 7. 优化二：词典跨度特征

**原理**：初始特征只有 4 个字符宽的视野，实体边界（跨度级决策）信息严重不足；`is_dictionary_char` 只回答"这个字在不在词典里"，是最弱编码。改进为把**词典在文本上的完整匹配结果**编码成每字符 6 项特征：

| 特征 | 含义 |
|---|---|
| `in_dict_span` | 位置是否被某词典短语完整覆盖 |
| `dict_boundary` | 在覆盖它的最长匹配中是 S/B/I/E 还是 O |
| `dict_label` | 覆盖它的最长匹配的实体类型（或 none） |
| `dict_span_len` | 最长匹配的长度桶（2 / 3-4 / 5-8 / 9+） |
| `dict_freq` | 该短语的训练词频桶（1 / 2-5 / 6-20 / 21+） |
| `label_conflict` | 覆盖它的多个匹配类型是否冲突 |

**实现**：`dict_span_features.py` 的 `DictSpanAnnotator`。词典口径与最终词典基线完全一致（min_count=1、min_length=2，25,206 条短语）；按首字建倒排索引，**5,000 条 dev 文本全部标注仅 1.3 秒**（对比全词典扫描法的 43 秒）。特征只来自训练集，不碰 dev/test 金标。

**实验 A**：沿用第一轮网格参数（C=1.0/none）+ 新特征，`small_model.py --dict-span-features` 跑出 Entity F1 **0.4201**，首次超过词典基线（0.4044）。预测实体数 20,432 与金标 20,300 几乎一致——模型学会了"词典说哪里是实体就跟随、词典没说的地方不瞎猜"。仅新增 28 个特征维度。

**过程记录（被覆盖）**：0.4201 是**中途成绩**，其配置（C=1.0/none + 跨度特征）在第八节被第二轮调参覆盖；该数字存档于 `outputs/grid/small_model_grid_C1.0_cw_none_span_metrics.json`。

## 8. 优化三：跨度特征基础上的第二轮调参

**原理**：超参数是在特定特征空间里选出来的。特征空间变了（+28 维、信息结构完全不同），旧参数的最优性失去依据，必须重搜。用小网格验证最可能反转的点：`C ∈ {0.1, 1.0}` × `class_weight ∈ {balanced, none}`。

**结果（趋势反转）**：

| C | class_weight | Entity F1 | P | R | 预测数 |
|---:|---:|---:|---:|---:|---:|
| **0.1** | **balanced ★** | **0.4301** | 0.3896 | 0.4799 | 25,004 |
| 0.1 | none | 0.4283 | 0.4290 | 0.4277 | 20,240 |
| 1.0 | balanced | 0.4217 | 0.3816 | 0.4712 | 25,064（收敛警告） |
| 1.0 | none（实验 A） | 0.4201 | 0.4187 | 0.4214 | 20,432 |

**发现**：第一轮"balanced 全面落后 none"的结论**反转**——跨度特征解决了边界难分的问题后，balanced 的虚报副作用消失，开始正常发挥"补偿稀有类型"的作用。最终配置定为 **C=0.1、class_weight=balanced、词典跨度特征开启、seed=42**，Entity F1 **0.4301**。

**过程记录（被覆盖）**：第七节的 0.4201 与第一轮结论"balanced 劣于 none"均被本节覆盖，全部旧数字在 `outputs/grid/` 中有存档。两轮 dev 调参已在报告中如实披露。

## 9. 优化四：消融实验（量化特征贡献）

**原理**：控制变量逐组移除——从最终配置出发，每次只拿掉一组特征，其余不变，成绩掉多少就归因给被拿掉的特征。实现上通过"列清零"等价于特征移除（线性模型下全零列权重恒为 0），特征构建只付一次成本。代码 `ablation_dict_features.py`，共 8 组，输出 `outputs/ablation/ablation_report.md/json`。

**结果**：

| 移除的特征 | Entity F1 | ΔF1 |
|---|---:|---:|
| 无（完整模型） | 0.4301 | — |
| label_conflict | 0.4304 | +0.0003 |
| in_dict_span | 0.4301 | 0.0000 |
| dict_freq | 0.4284 | -0.0017 |
| dict_boundary | 0.4256 | -0.0045 |
| dict_span_len | 0.4163 | -0.0137 |
| dict_label | 0.2796 | **-0.1504** |
| 全部跨度特征 | 0.1808 | -0.2493 |

**结论**：
1. `dict_label` 贡献了总增益的约 60%，是跨度特征的核心——小模型最缺的不是"实体在哪"，而是"实体是什么类型"；
2. `in_dict_span` 完全冗余（信息被 dict_label 包含），`label_conflict` 处于噪声水平；
3. 六组单独贡献之和（约 0.17）小于总贡献（0.2493），特征间存在**协同效应**；
4. "全部移除"的 0.1808 与第一轮网格同配置无跨度特征的结果（0.1809）互相印证，是实验可复现性的证据。

## 10. 复现收尾（工程工作）

| 事项 | 说明 |
|---|---|
| `--eval-file` + predict-only | 三个基线统一支持对无金标文件（CMeEE_test.json）预测：自动检测无金标，只写 `*_test_predictions.json`，不计算指标 |
| 一键复现 runner | `run_final_baselines.py` 按 `configs/final_baseline.json` 依次执行：纯规则 → 最佳词典 → 小模型 → 3 个错误分析 → 实验汇总 |
| 环境冻结 | `requirements.txt`：Python 3.12.7、numpy 2.3.4、scikit-learn 1.9.0 |
| 指标刷新机制 | `evaluate_saved.py --batch-dir outputs`（见第 2.2 节） |
| 小模型参数化 | `--seed/--C/--class-weight/--dict-span-features`，默认值与最终配置一致 |

**过程中修复的 bug（不足记录）**：
1. 早期 `run_final_baselines.py` 向 `small_model.py` 传 `--seed/--C/--class-weight`，但接收方没有这些参数——完整跑 runner 时小模型步骤会崩溃；
2. `is_dictionary_char` 特征原先对每字符遍历全部词典短语（O(字符数×短语数)），特征提取是小时量级——预计算字符集合后降到 **0.9 秒/81 万字符**；
3. 本环境 DictVectorizer 输出 int64 稀疏索引（scikit-learn 拒绝接收），`sparse_int32` 改为显式 int32 构造。

### 12.6 复现注意事项

1. **test 没有公开金标**，`entities` 全为空不代表没有实体——空列表不能当负标签，不能计算 P/R/F1；
2. 本文档所有数值均为 **dev 集开发结果**，不能写成官方 test 成绩；
3. 小模型超参数经**两轮 dev 调参**选出，报告中须如实披露；
4. 被覆盖的中间结果（0.1745 / 0.2281 / 0.4201 等）在 `outputs/grid/` 中有存档，可追溯；
5. 全部方法使用同一版训练集（`data_cleaned/CMeEE_train_cleaned_final.json`）、同一份 dev 金标和同一套评测代码。

## 13. 已知不足与边界

1. **传统方法天花板**：词典/规则/字符级线性模型的信息量上限在实体级 F1 约 0.5 左右；公开资料中 CMeEE dev 的 0.6+ 成绩来自预训练语言模型微调（成员 3 方向）。本文档的最佳 0.4301 已接近非大模型路线的头部水平；
2. **BIO 单层限制**：小模型训练目标采用最长非重叠投影，无法完整学习嵌套实体的多层标注（多标签字符指标可部分缓解评测盲区，但模型本身仍只输出单层）；
3. **错误分析口径**：边界错误匹配只接受"同类型 + 重叠"，不同类型但重叠的 gold/pred 会被拆成漏检+误报两条；
4. **第一轮网格缺一组**：C=10.0/none 因训练耗时且趋势无竞争力被跳过（grid 汇总中有标记）；
5. **dev 调参风险**：两轮网格 + 消融共在 dev 上做了多次选择，存在轻微过拟合 dev 的风险，已按协议披露。
