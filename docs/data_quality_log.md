据此可确认官方 CMeEE 测试集用于无公开答案的预测/提交流程。本地全部为空的实体列表与这一用途相符，但这属于基于官方说明的推断：尚不能证明本地文件来自该版本，也不能证明官方原文件必定采用空列表而不是其他表示方式。

仍待补充：实际下载链接、下载日期、版本、数据使用协议，以及本地文件与上游版本的一致性证据。仓库代码许可不能直接作为数据许可结论。

## 重复文本标注一致性检查

### 检查目的
检查训练集中完全相同文本的多条记录是否具有一致的实体标注，为后续的数据质量复核提供依据。

### 检查方法
- 按 `text` 字段完全相同进行分组，不做去空格、文本规范化等处理。
- 比较每条记录的实体标注四元组：`(start_idx, end_idx, type, entity)`。
- 比较时忽略实体列表的排列顺序，但保留重复实体。
- 本次检查只生成报告和复核表，不修改原始数据，不自动判断标注正误。

### 检查结果
- 训练集记录数：15,000。
- 完全重复文本组数：43。
- 标注一致组数：25。
- 标注不一致组数：18。
- 分类统计：`type_conflict` 2 组，`possible_missing_entity` 7 组，`boundary_conflict` 1 组，`multiple_conflicts` 8 组。
- 复核 CSV：43 行。
- 报告解析失败：0。
- 所有复核状态初始为 `pending`。

### 结果解释与限制
以上分类描述的是重复文本之间的标注差异，不等同于已确认的错误标注。需要依据适用的标注规范进一步人工复核。当前未对不一致记录进行自动修复，也未修改原始 JSON 文件。
